# boss 直聘求职端自动化

一个本地运行的求职流程工作台，用来管理简历、岗位池、公司尽调、岗位排序、打招呼话术、AI 深度报告和上线前维护检查。

项目定位不是简单的岗位抓取脚本，而是一个完整的个人求职操作系统：从岗位获取、JD 清洗、企业工商核验、风险判断、简历匹配、排序决策，到受控打招呼和后续复盘，尽量把每天重复、容易遗漏的动作沉淀成可追踪的流程。

当前版本：`1.0.0`。项目已完成上线前数据清理，仓库不包含本地岗位池、简历 PDF、BOSS Cookie、浏览器 Profile、API 调用日志、验收截图或测试运行数据。

## 核心能力

- 简历解析、优化、版本保存、版本对比、PDF 预览与导出。
- BOSS 岗位抓取、城市搜索、多维筛选、岗位导入、JD 详情补全。
- 岗位池治理：重复岗位合并、疑似过期标签、企业黑名单、删除恢复、质量体检。
- 企业尽调：腾讯云工商 API、百度搜索证据、AI 行业趋势与风险分析。
- 岗位排序：简历匹配、公司风险、用户偏好、权重模板、排序解释。
- 智能求职助理：投递策略、JD 质量识别、简历反推建议、面试准备、跟进提醒。
- 打招呼工作台：候选筛选、岗位批量勾选、话术生成、校验、dry-run、人工确认、灰度自动发送、失败恢复、回复复盘。
- 仪表盘：全流程状态、求职漏斗、CRM 看板、30 天趋势、数据质量体检、任务恢复中心。
- 设置与维护：API 配置、加密密钥存储、备份恢复、SQLite 迁移、隐私扫描、发布检查。
- 帮助中心：按模块提供适用场景、推荐步骤、完成信号、常见失败和修复动作。

## 技术栈

- 后端：Python 3.9+、FastAPI、Pydantic、ReportLab、Pillow、SQLite/JSON 本地存储。
- 前端：React 19、TypeScript、Vite、Vitest、Playwright。
- 外部服务：OpenAI 兼容 AI Provider、百度千帆智能搜索、腾讯云云市场工商 API。
- 自动化浏览器：BOSS 页面正常浏览器操作，不绕过登录、验证码或风控。

## 快速启动

首次启动前，先安装依赖并构建前端：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
```

后端依赖可在项目根目录执行：

```bash
cd backend
python3 -m pip install -e .
```

启动应用：

```bash
cd ..
./start.sh
```

启动后访问：

```text
http://127.0.0.1:5173
```

`start.sh` 会在启动前检查 Python、pnpm、前端构建产物、数据目录和端口状态。如果 `5173` 已被占用，需要先关闭旧服务或换端口手动启动。

## 常用命令

后端全量测试：

```bash
cd backend
pytest -q
```

前端类型检查、单测和生产构建：

```bash
cd frontend
pnpm validate
```

浏览器端到端测试：

```bash
cd frontend
pnpm exec playwright test
```

发布前质量门禁：

```bash
python3 scripts/release_check.py
```

预览发布检查项：

```bash
python3 scripts/release_check.py --dry-run
```

桌面端打包：

```bash
python3 scripts/build_desktop.py mac
```

打包后会生成 macOS 安装包：

```text
release/desktop/boss 直聘求职端自动化-1.0.0-arm64.dmg
```

桌面端会内置前端页面、后端服务、Python 运行环境、运行依赖和 Chromium 浏览器运行时；用户数据会写入系统应用数据目录，不会把开发目录里的 `data/` 测试数据打进安装包。BOSS 登录、抓取和受控自动沟通会优先使用安装包内置浏览器，不要求普通用户额外安装 Python、Node、pnpm 或 Chrome。后端以目录式运行包封装，避免每次启动都解压单文件运行环境。

## GitHub 自动打包

项目已接入 GitHub Actions 桌面端自动打包：

- 首次打包：在 GitHub Actions 中手动运行 `Desktop Release`。
- 后续发版：创建并推送版本标签，例如 `v1.0.1`，会自动打包并上传 GitHub Release。
- 构建矩阵：macOS Intel、macOS Apple Silicon、Windows x64、Linux x64。

发版命令示例：

```bash
git tag v1.0.1
git push origin v1.0.1
```

手动触发会生成预发布版本；版本标签触发会生成正式 Release。macOS 当前为未签名安装包，首次打开可能出现系统安全提示；后续如需正式分发，可接入 Apple Developer 签名、公证和 Windows 代码签名。

## 推荐使用流程

1. 打开“设置”，配置 AI Provider、百度搜索、腾讯云工商 API，并确认运行模式。
2. 进入“简历”，上传或补全简历，保存一个基础版本。
3. 进入“岗位”，选择城市、关键词和筛选条件，抓取或导入岗位。
4. 在岗位池质量板块处理缺失 JD、重复岗位、疑似过期岗位和黑名单命中。
5. 进入“尽调”，对重点公司执行一键尽调，复核工商名称、风险证据和行业分析。
6. 进入“排序”，选择权重模板，生成推荐顺序和解释。
7. 进入“打招呼”，按岗位页已选、可直接发送、未打招呼、缺少话术、缺少 JD、决策推荐、低风险等范围筛选本次批量岗位，先 dry-run 生成话术，再校验、人工确认或小批量灰度发送。
8. 回到“仪表盘”，查看求职漏斗、CRM 看板、趋势图、跟进提醒和失败恢复。
9. 上线或迁移前，在“设置与维护”执行脱敏备份、隐私扫描、PDF 视觉回归和发布检查。

## 配置说明

主要配置都在前端“设置”里维护：

- AI Provider：支持 OpenAI 兼容接口，可配置 Provider、Base URL、模型和 API Key。
- 百度千帆智能搜索：用于公司舆情、证据链接和搜索摘要。
- 腾讯云企业工商 API：用于工商基础信息、股东、高管、经营异常、处罚、失信、被执行等结构化数据。
- 用户偏好：稳定性、薪资、成长、匹配度、规避行业、偏好城市，会进入排序和 AI 报告。
- 运行模式：生产、演示、测试。生产模式默认禁止示例抓取，防止演示数据混入真实岗位池。

密钥会优先使用本地加密存储。完整密钥导出需要一次性确认令牌，发布前可使用维护区的隐私扫描和安全审计检查明文风险。

## 数据与存储

默认业务数据保存在本地 `data/` 目录。项目支持 JSON 兼容副本和 SQLite 主存储切换：

- 岗位池、尽调、排序、简历、维护日志和外部 API 调用日志已接入统一存储。
- 设置页提供 SQLite 迁移、备份、恢复预览、设为主存储和回滚 JSON。
- 删除岗位会先进入回收站，可在设置维护区恢复。
- 数据清理预演只展示将处理的数据类型和数量；确认后才会归档或清理。

建议在大批量操作、迁移、上线或打包前先导出脱敏备份。

仓库上线前已清理本地运行数据。首次启动后，应用会重新创建干净的数据目录；桌面端则会使用系统应用数据目录保存用户自己的简历、岗位、Cookie、日志和配置。

## 安全边界

- 应用默认只允许本机访问；如需局域网访问，必须显式设置 `BOSS_WORKBENCH_ALLOW_REMOTE=true`。
- 自动打招呼只执行正常浏览器页面操作。
- 遇到未登录、Cookie 失效、验证码、页面风控或页面结构变化，会停止并记录失败原因。
- 不绕过验证码、不规避平台风控、不做高频无节制发送。
- 真实自动发送默认需要灰度验证，建议先小批量测试并人工复核。

更多密钥轮换与安全说明见 [docs/SECURITY.md](docs/SECURITY.md)。

## 常见问题

### 页面提示接口 Not Found

通常是后端服务还没有重启，或前端正在请求旧进程。重新执行 `./start.sh`，确认访问的是 `http://127.0.0.1:5173`。

### 桌面端系统检查提示环境项

桌面端已内置 Python、前端页面、后端服务和 Chromium。系统检查中的 Python、pnpm、前端构建只作为源码开发参考，不是普通桌面用户必须安装的环境。桌面端真正需要关注的是数据目录、API 配置、BOSS 登录状态和网络连通性。

### 帮助中心一直加载

当前版本已增加内置帮助兜底。若接口失败，会显示内置帮助、失败原因和“重试加载”按钮。

### BOSS 登录状态失败

可能是未登录、Cookie 失效、网络失败、页面风控或页面结构变化。先在浏览器中人工确认 BOSS 状态，再回到岗位或打招呼模块重试。

### 打招呼批量发送如何控制范围

打招呼页提供“本次批量范围”和岗位列表上方的快捷管理条。可以先按未打招呼、可直接发送、缺少话术、决策推荐、低风险等范围筛选，再对当前范围执行全选、取消、反选或清空。dry-run、校验、预检、人工确认和自动打开 BOSS 发送都只作用于本次已选岗位。

### PDF 生成或视觉检查异常

先在设置维护区运行 PDF 真实渲染检查。当前视觉回归已使用独立渲染目录，避免旧缓存或并发写入导致图片损坏。

### 生产模式不能生成示例数据

这是预期行为。生产模式默认禁止示例抓取，防止污染真实岗位池。如需演示，请切换到演示模式或测试模式。
