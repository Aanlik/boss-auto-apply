# 智能打招呼工作台开发文档

## 目标定位

智能打招呼不是高频群发工具，而是一个半自动、可审核、可恢复、可追踪的求职触达工作台。

核心目标：

- 帮用户基于岗位 JD、简历、公司风险和求职偏好生成更自然的招呼语。
- 在发送前提供预览、编辑、校验和人工确认。
- 对登录、风控、重复触达、失败任务、发送记录做可解释管理。
- 与岗位状态、投递时间线、任务中心、审计日志联动。

明确不做：

- 不做绕过平台风控的高频自动群发。
- 不做无人工审核的默认批量发送。
- 不做多账号批量运营、商业化代投或骚扰式触达。
- 不保存不必要的个人隐私和平台敏感凭据。

## GitHub 调研参考

本设计参考了以下开源项目的产品和工程思路：

- [longsizhuo/BossZhiPin_Job_Search](https://github.com/longsizhuo/BossZhiPin_Job_Search)：独立浏览器 Profile、LLM 生成招呼语、dry-run、发送前校验、JSONL 审计日志。
- [engvuchen/boss-zhipin-robot-web](https://github.com/engvuchen/boss-zhipin-robot-web)：Web 控制台、筛选条件、静默运行、错误通知、不同沟通窗口形态处理。
- [as161233574-alt/boss-zhipin-bot](https://github.com/as161233574-alt/boss-zhipin-bot)：FastAPI + Playwright + SQLite，全流程任务状态、每日上限、重复投递保护、浏览器锁、自动回复和投递漏斗。
- [WindAndDream/boss-auto-greeting](https://github.com/WindAndDream/boss-auto-greeting)：油猴脚本路线，适合轻量使用，但不适合作为本项目主架构。

结论：本项目应采用“受控任务 + 人工审核 + 审计日志”的路线，而不是简单页面脚本。

## 用户流程

### 1. 选择候选岗位

入口：

- 岗位模块批量选择。
- 排序模块推荐结果。
- 尽调完成后的公司页面。
- 仪表盘下一步建议。

候选过滤条件：

- 岗位状态：未打招呼、观察中、推荐投递。
- JD 完整度：优先完整 JD；缺失 JD 需提示先补全。
- 公司黑名单：命中黑名单自动跳过。
- 企业风险：高风险公司默认不进入候选，用户可手动放行。
- 重复保护：同岗位、同公司、同 HR、近 48 小时已沟通过的记录自动跳过。
- 求职偏好：城市、薪资、稳定性、成长性、规避行业。

### 2. 生成招呼语

输入上下文：

- 岗位标题、薪资、城市、经验、学历、JD。
- 公司工商名称、行业、公司风险摘要。
- 排序分、简历匹配度、简历缺口。
- 用户当前激活简历摘要。
- 用户偏好和招呼语风格设置。

生成要求：

- 中文自然表达，避免模板感。
- 长度默认 80-180 字。
- 不夸大经历，不承诺虚假能力。
- 不包含联系方式，除非用户显式允许。
- 能体现岗位相关性和 1-2 个简历亮点。

### 3. 发送前审核

每条招呼语进入审核列表，用户可：

- 查看岗位和公司摘要。
- 查看生成招呼语。
- 编辑内容。
- 重新生成。
- 标记跳过。
- 单条发送。
- 勾选多条后批量发送。

发送前必须通过校验：

- 内容非空。
- 长度在配置范围内。
- 包含中文字符。
- 无 AI 错误话术，例如 `Error`、`Traceback`、`As an AI`、代码块。
- 无未替换模板变量，例如 `{company}`、`{{job}}`。
- 与最近发送内容相似度不能过高。
- 当前岗位未被黑名单或重复规则拦截。

### 4. 执行发送

发送任务要求：

- 使用统一任务中心记录任务。
- 使用浏览器操作锁，避免 JD 抓取、打招呼、聊天监控互相抢页面。
- 每次发送前检查登录状态、验证码、页面风控、网络状态。
- 支持 dry-run 模式，只生成和记录，不触发真实发送。
- 支持单次上限、每日上限、失败熔断。
- 发送间隔使用用户配置的低频范围。

### 5. 发送后联动

发送成功：

- 岗位状态更新为 `contacted` 或 `greeted`。
- 写入岗位 `status_history`。
- 写入投递时间线。
- 写入维护审计日志。
- 写入招呼语审计记录。
- 可补充人工验收记录，保存验收人、检查项、结果和备注。
- 可记录 HR 回复类型、回复摘要和下一步动作，用于后续跟进。

发送失败：

- 保留失败原因。
- 进入任务中心恢复区。
- 根据错误类型给出建议动作。
- 不改变岗位为已打招呼。

## 状态设计

### 招呼语状态

- `draft`：已生成，待审核。
- `edited`：用户已编辑。
- `approved`：已通过人工确认。
- `sending`：发送中。
- `sent`：发送成功。
- `skipped`：用户跳过或规则跳过。
- `failed`：发送失败。
- `blocked`：登录、风控、验证码、黑名单等原因阻断。

### 失败原因分类

- `not_logged_in`：未登录。
- `cookie_expired`：Cookie 失效。
- `risk_control`：页面风控或验证码。
- `network_error`：网络失败。
- `page_changed`：页面结构变化，找不到按钮或输入框。
- `job_closed`：岗位关闭或不可沟通。
- `already_contacted`：已沟通过。
- `blacklisted_company`：企业黑名单命中。
- `validation_failed`：招呼语校验失败。
- `rate_limited`：达到单次或每日上限。

### API 草案

- `POST /api/greetings/candidates`
  - 根据筛选条件返回可打招呼岗位候选。

- `POST /api/greetings/drafts`
  - 批量生成招呼语草稿。

- `GET /api/greetings`
  - 查询招呼语列表，支持按状态、岗位、批次筛选。

- `PATCH /api/greetings/{id}`
  - 修改招呼语内容、状态或备注。

- `POST /api/greetings/{id}/regenerate`
  - 单条重新生成。

- `POST /api/greetings/validate`
  - 校验单条或批量招呼语。

- `POST /api/greetings/send`
  - 发送已确认的招呼语。

- `POST /api/greetings/dry-run`
  - 只执行候选、生成、校验和日志，不真实发送。

- `GET /api/greetings/batches`
  - 查询批次列表。

- `GET /api/greetings/stats`
  - 查询触达统计、成功率、失败原因、重复跳过数量。

### 服务分层

- `GreetingCandidateService`
  - 负责候选岗位筛选、黑名单过滤、重复保护。

- `GreetingGenerator`
  - 负责基于 JD、简历、公司、排序结果生成招呼语。

- `GreetingValidator`
  - 负责长度、中文、异常话术、模板变量、重复相似度检查。

- `GreetingSender`
  - 负责浏览器动作、登录检查、页面安全检查、发送执行。

- `GreetingAuditStore`
  - 负责审计日志、状态历史、任务中心和投递时间线联动。

### 任务中心联动

任务类型：

- `greeting_generate`
- `greeting_validate`
- `greeting_send`
- `greeting_dry_run`

任务元数据：

- 批次 ID。
- 岗位数量。
- 已处理数量。
- 成功数量。
- 跳过数量。
- 失败数量。
- 当前失败原因。
- 可恢复动作。

## 前端设计

### 页面入口

建议在“打招呼”模块增加工作台式页面：

- 顶部：批次状态、今日剩余额度、登录状态、风控状态。
- 左侧：筛选候选岗位。
- 中间：招呼语审核列表。
- 右侧：岗位/JD/公司/简历匹配摘要。

### 关键组件

- 候选岗位筛选卡片
  - 状态、城市、薪资、标签、决策标签、公司风险、JD 完整度。

- 批次控制栏
  - 生成草稿、重新生成、校验、dry-run、发送选中、暂停。

- 招呼语审核卡片
  - 岗位标题、公司名称、匹配分、风险标签、重复提示、编辑框、校验结果、发送状态。

- 失败恢复区
  - 展示失败原因和建议动作，例如重新登录、降低频率、重新定位页面元素、人工处理。

- 触达统计面板
  - 今日生成、今日发送、成功率、跳过原因、失败原因、回复率。

### UI 原则

- 默认先预览，不默认发送。
- 发送按钮需要明显确认状态。
- 批量发送前展示将发送数量、跳过数量、风险数量。
- 黑名单、重复、风控等阻断原因要比“失败”更具体。
- dry-run 模式需要显著标识，避免用户误以为已经发送。

## 安全与合规边界

- 默认关闭真实发送能力，用户需显式开启。
- 默认启用人工审核。
- 默认启用每日上限和单次上限。
- 遇到验证码、风控、账号异常立即停止任务。
- 审计日志不保存平台 Cookie、完整手机号、微信号等敏感信息。
- 导出数据需复用现有隐私扫描与脱敏策略。
- 不提供绕过验证码、绕过风控或规避平台限制的能力。

## 验收标准

### 后端

- 候选岗位能正确排除黑名单、重复沟通、缺失 URL 和高风险公司。
- 招呼语生成支持 AI 和规则兜底。
- 校验器能拦截异常 AI 内容、空内容、过长内容和模板变量。
- dry-run 不触发真实发送，但完整写入审计日志。
- 发送失败能返回结构化失败原因。
- 成功发送后能更新岗位状态、状态历史和投递时间线。
- 后端测试覆盖候选、生成、校验、dry-run、发送结果联动。

### 前端

- 用户可以批量生成、编辑、校验、发送招呼语。
- 页面展示今日额度、登录状态、任务状态和失败原因。
- 批量发送前有确认摘要。
- 失败任务可在任务中心看到，并能按建议恢复。
- dry-run 和真实发送状态有清晰区分。

### 端到端

- Playwright 覆盖：
  - 生成草稿。
  - 编辑草稿。
  - 校验失败。
  - dry-run。
  - 模拟发送成功。
  - 模拟登录失效。
  - 模拟风控阻断。
